⏺ The Bug

  The Hailege PC817 module you bought is not the simple 2-pin (signal + GND)
  variant my docs assumed. It's a 3-pin input variant:

  Module input side (per channel):
    VCC ──[510 Ω]──► LED anode
                      LED cathode ── IN
    GND ─────────────── (separate)

  The LED is between VCC and IN. The LED is ON when IN is pulled LOW
  (active-LOW). The reason you see the indicator LED flicker when keying is that
  some parasitic current is leaking through the input, but the optocoupler LED
  is never getting its full drive current because VCC is floating — there's no
  path from a positive supply.

  Your wiring is therefore wrong in two ways:

  1. VCC is not connected. The LED draws current from VCC through the on-board
  resistor. With VCC floating, the LED only gets gated leakage through the GPIO
  when it's HIGH — which is why you see a flicker but no real keying.
  2. GPIO polarity is inverted. Even if you wire VCC and GND correctly, the
  radio will key when GPIO4 is LOW, not HIGH. That's the opposite of the current
  firmware.

  Two ways to fix it

  Option A — rewire + invert GPIO in firmware (recommended, keeps the 
  radio-keying code simple)

  Wiring:
  Cardputer 3.3V  → Module VCC (input)
  Cardputer GND   → Module GND (input)
  Cardputer GPIO4 → Module IN

  Then in radio_keyer.cpp, change the GPIO logic: drive HIGH when bus is idle
  (pull-up effect), drive LOW when keyed. Activating the input requires the
  firmware to sink current, which the ESP32-S3 GPIO can do.

  Option B — rewire to ignore VCC, drive only from GPIO

  This is what my docs originally assumed, but it requires the simple 2-pin
  variant. The Hailege module has a 510 Ω resistor to VCC, so without VCC
  connected you can't get enough current. You'd need to bypass the on-board
  resistor.
